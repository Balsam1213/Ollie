## 2. 迭代详细卡

### v1.1 · 实机验收与收尾（0.5–1 周）

**目标**：v1 从"代码完成"变成"桌上摆着一只活的 Ollie"。

**内容与实现方式**（零新模块，只调参）：
- M0–M7 逐项验收，规程照 [procedures.md](procedures.md) §4–§6，结果记 devlog
- 光敏四场景标定 → 改 `Config.h` 两个 ADC 阈值
- 脸部观感调参：只动 `Face.cpp` 顶部几何常量（眼位/尺寸/嘴弧），Wokwi 上预调、实机微调
- `PET_WAKE_ENABLED` 打开试玩一周，决定默认值去留

**效果优化点**：LED_MAX 亮度封顶按实物观感复核；蜂鸣器音量/频率实测调整。

**验收**：devlog/TODO 的 v1 实机验收组全勾；过夜长测通过（heap 稳定）。

### v2.0 · AI 聊天·文字（1–2 周）★核心迭代

**目标**：手机浏览器打字和 Ollie 聊天，回复带着情绪、表情跟着变；断网自动退回纯离线宠物。

**新增模块**（遵循现有架构约束，全部非阻塞、配置进 Config.h）：

| 模块 | 职责 | 实现要点 |
|---|---|---|
| `NetConfig` | WiFi 连接与凭据管理 | 凭据存 NVS；首次启动起 SoftAP 配网页（手机连入填写）；连接失败不重试刷屏，按退避策略重连 |
| `WebChat` | 局域网聊天页 + 配置页 | ESP32 自带 WebServer；页面存 PROGMEM（对话气泡 UI，手机优先）；配置页写 API key/接口地址/模型名 → NVS |
| `LLMClient` | 大模型调用 | WiFiClientSecure + HTTP POST，OpenAI 兼容 `/chat/completions` 格式（DeepSeek/GLM/Qwen flash 档通吃）；10s 超时 |

**核心实现细节**：
- 人设 prompt（PROGMEM 模板）：Ollie 性格 + **当前三项数值快照注入**（为 v2.2 状态感知铺路）+ 要求只输出 JSON `{"reply":"...","emotion":"happy|calm|hungry|sleepy"}`；回复 ≤50 字（为 TTS 铺路）
- 情绪映射：`emotion` 字符串 → `face.setExpression(Emotion, 3000)`——v1 预留的解耦接口在此兑现；映射表独立函数便于单测
- 断网降级（兑现 requirements NFR-2x1）：WiFi 失败/请求超时 → 标志位切回纯离线模式，心情灯蓝闪一次提示；离线玩法代码路径零改动
- 请求在调度器里做状态机（连接→发送→收包→解析），不阻塞渲染帧率

**验收标准**：手机连同一 WiFi 打开网页聊天正常往返（本地网络 ≤2s）；表情随 emotion 变化；拔路由器 3s 内回离线模式且按键/睡眠一切照旧；仓库与固件默认值中均无 API key。

**风险与对策**：TLS 峰值内存（实测 heap 基线 ~300KB + 8MB PSRAM，余量充足，必要时开 PSRAM 分配）；各家 API 字段差异 → 统一走 OpenAI 兼容格式并在配置页可换端点；回复超时 → 表情回平静 + 网页提示，不卡死。

### v1.2 · 体验优化包·一（0.5–1 周，穿插）

**目标**：不联网也越看越有生命感。

**内容与实现方式**：
- **个性动画库**：`Face` 增加 idle 动作表（动作名/触发条件/时长/绘制偏移）：打哈欠（困倦阈值得分接近时）、歪头（随机低频）、无聊小动作（>2h 无互动时叹气式动画）。复用现有 drift/blink 的时段驱动模式
- **音效库**：`Buzzer` 从单音升级为**音符序列播放器**（音符表 {频率,时长} 数组 + 时间轴推进，仍非阻塞）：喂食"叮咚"、抚摸"咕噜"、入睡三音符摇篮短句、晨起升调
- **RGB gamma 校正**：MoodLight 输出按 gamma 2.2 查表修正，低亮度段过渡更自然

**验收**：每种动画/音效可被对应条件触发；`test/` 补 Buzzer 序列推进与 idle 触发判定的单测；30fps 不掉帧。

### v2.1 · 语音对话（2–3 周）

**目标**：按住说话，Ollie 用声音回答——AI 聊天的完整形态。

**硬件**（约 ¥25）：INMP441 I2S 麦克风、MAX98357A I2S 功放、2寸 4Ω 3W 小喇叭；接预留的 GPIO12/13/14（麦克风 SCK/WS/SD）+ 16/17/18（功放 BCLK/LRC/DIN）。

**新增模块**：
| 模块 | 职责 | 实现要点 |
|---|---|---|
| `AudioIn` | I2S 采集 | 16kHz / 16bit / 单声道 PCM，环形缓冲（PSRAM），按键按住期间写缓冲 |
| `AudioOut` | I2S 播放 | 接收音频分片流式回放；与 Buzzer 共存时仲裁（语音播放期间蜂鸣静音） |

**交互设计**：**长按抚摸键说话**（不加新按键：长按 >600ms 进录音态，松手发送；短按仍是抚摸）——按键时长判定放 Buttons 模块，事件扩展。

**ASR/TTS 选型**（二选一，开工前定）：
1. **首选：直连小智服务端协议**（xiaozhi-esp32，MIT）——ASR/LLM/TTS/会话全链路现成，省掉自建；文本生成仍用我们自己的 LLMClient 人设或直接用其管线，开工时权衡
2. 备选：自串云端（讯飞/火山 ASR + TTS），可控性高但工作量大、多份密钥

**延迟处理**：录音结束→出声之间 1–3s，用"思考中"动画掩盖（眼珠快速左右+嘴部省略号循环）——又是表情引擎的活。

**验收**：按住说话 1–3s 出声回答；说话期间表情进入聆听态；断网时语音功能提示不可用并自动回文字/离线；喇叭无持续底噪（功放使能脚控制）。

**风险**：麦克风底噪/回声（增益调参、必要时简单的能量门限）；网络抖动（分片重试）；内存（音频缓冲全放 PSRAM）。

### v2.2 · 唤醒词与情绪回流（1–2 周）

**目标**：叫名字就应答；聊天真的影响它的心情——"养成"与"聊天"融合的差异化卖点在此闭环。

**内容与实现方式**：
- **本地唤醒词**：ESP-SR WakeNet（乐鑫官方，8MB PSRAM 足够）；唤醒后播唤醒动画+音效并进入聆听态；待机时 AFE 降噪持续跑（CPU 预算复核：双核，一个核跑音频流水线）
- **情绪回流**：LLM 输出 JSON 增加 `mood_delta`（-5..+5）字段 → `Stats` 增减心情值 → 灯色渐变；对话被凶了灯真的变橙红
- **对话记忆**：最近 N 轮（N≈8）存 PSRAM，随请求发送；重启清空（桌宠设定：睡一觉忘掉烦心事，反而省心）
- **状态感知回答**：v2.0 已注入数值快照，此处让回答真正引用状态（"我饿了"→它按当前饱食度回应，且喂食键效果在对话里被提及）

**验收**：安静房间叫名唤醒率正常、日常误唤醒 ≤1 次/天；连续聊开心话题后心情灯变青绿、数值可查；对话内容与三项数值状态一致。

## 4. 版本与发布规范

- **版本号**：semver。破坏性（玩法/数据不兼容）升 major；新能力（新模块/新交互）升 minor；调参/修 bug 升 patch
- **发布**：每个迭代完成 = 三层验证全绿（单测/编译/仿真，涉硬件加实机验收）+ 文档同步（requirements/tech-spec/本表状态列）+ devlog 记录 + git tag（如 `v2.0.0`）
- **发布前检查单**：`pio run` 通过 · `bash test/run_tests.sh` ALL PASS · 仓库无密钥 · TODO 勾选 · roadmap 状态列更新
