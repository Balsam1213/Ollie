# Ollie v1 可行性评定与实施计划

> ESP32-S3 桌面电子宠物 · 离线版（v1） · 2026-10-25

## 一、可行性评定

**结论：完全可行，难度属于"入门偏上"，v1 没有任何技术阻碍。**
硬件全部是常见低价模块，软件不依赖任何刁钻的库；真正的工作量不在电路，而在表情动画的打磨。

### 逐项评定

| 模块 | 方案 | 可行性 | 说明 |
|---|---|---|---|
| 主控 | ESP32-S3-DevKitC-1 N16R8 | ★★★★★ | 双核 LX7 240MHz + 512KB SRAM + 16MB Flash + 8MB PSRAM。脸部渲染和状态机的负载不到它的 5%，余量极大 |
| 显示 | SSD1306 128×64 I2C | ★★★★★ | 最成熟的组合。I2C 400kHz 下全帧刷新约 23ms，跑 30fps 绰绰有余 |
| 表情动画 | GFX 图元自绘 | ★★★★☆ | 没有现成库能画"脸"，需自写约 200 行绘制代码。这是本项目**主要工作量**，也是乐趣所在 |
| 按键互动 | GPIO + 消抖 | ★★★★★ | 无难度 |
| 数值存档 | NVS（Preferences 库） | ★★★★★ | 核心自带，带磨损均衡。每分钟写一次的量级，Flash 寿命按 20 年以上计，无需担心 |
| 昼夜感知 | 光敏 AO → ADC | ★★★★★ | 注意用 ADC1 的引脚（GPIO1–10）；"持续变暗 10 秒"本身就是很好的防抖设计 |
| 心情灯 | 板载 WS2812 (GPIO48) | ★★★★★ | arduino-esp32 内置 `rgbLedWrite()` 驱动，无需额外库、无需接线 |
| 蜂鸣器 | LEDC 方波 | ★★★★★ | 无源蜂鸣器直接 GPIO 驱动，小蜂鸣器电流在 IO 驱动能力内 |
| v2 AI 聊天 | WiFi + LLM API + I2S 音频 | ★★★☆☆ | 可行，但工作量约为 v1 的 2–3 倍，难点在音频链路和延迟，见第六节 |

### 已确认的设计修正：睡觉恢复精力

原设定中三项数值只降不升、睡觉只停不回，**精力第一次降到 0 之后就永远是 0**，Ollie 会永远挂困倦脸。已确认修正为：

> **睡眠期间精力 +2/分钟**（饱食度和心情仍保持停掉）。

睡觉因此有了意义：困了让它睡，睡饱自然回。

### 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OLED 静止画面灼伤 | 长期显示残影 | 眨眼/眼动本身就是缓解；再加两条：整脸位置每 30s 随机漂移 1px；睡眠时屏幕对比度调低 |
| 光敏临界值抖动 | 睡眠/醒来反复横跳 | 10 秒持续判定 + 迟滞：ADC < 800 判暗入睡，> 2000 才判亮醒来（阈值按实测标定，见 M5） |
| 按键机械抖动 | 一次按压触发多次 | 20–50ms 时间窗消抖 |
| arduino-esp32 3.x 的 LEDC API 变更 | 照老教程抄会编译不过 | 新 API 是 `ledcAttach(pin, freq, res)`，不再是 `ledcSetup` + `ledcAttachPin`。本计划按 3.x 写 |
| S3 串口打不出 | 以为板子坏了 | Arduino IDE 板子选项里打开 **USB CDC On Boot: Enabled** |
| 数值衰减节奏太慢难调试 | 100 分钟才能看全程 | 代码里留 `DEBUG_FAST_DECAY` 宏：定义后衰减改为 1 点/秒 |
| 板载 WS2812 太亮刺眼 | 桌面夜间晃眼 | 亮度封顶（RGB 各通道上限约 40/255），呼吸效果本身也压亮度 |

### 成本与工期

- 硬件：主控 ¥35–50 + OLED ¥8 + 光敏/蜂鸣器/按键 ≈ ¥10，**合计 ¥60 以内**（心情灯用板载，零成本）
- 工期：新手约 **2–3 周业余时间**（6–9 个晚上）；有 ESP32 经验约 2–3 天

## 二、硬件与接线

### BOM

| 器件 | 数量 | 说明 |
|---|---|---|
| ESP32-S3-DevKitC-1 N16R8 | 1 | 16MB Flash / 8MB 八线 PSRAM |
| 0.96" OLED SSD1306，I2C 4 针 | 1 | 地址一般是 0x3C |
| 光敏电阻模块（带 AO 输出） | 1 | 必须用 AO，别只接 DO |
| 无源蜂鸣器 | 1 | 无源，靠 PWM 出声 |
| 轻触开关 | 2 | 喂食、抚摸 |
| 面包板 + 杜邦线 | 若干 | v1 不做外壳 |

### 引脚分配表（v1 定稿，已避开所有坑）

| 功能 | GPIO | 备注 |
|---|---|---|
| OLED SDA | 8 | S3 的 Wire 默认引脚，板上一般有丝印 |
| OLED SCL | 9 | 同上 |
| 按键 · 喂食 | 4 | 另一脚接 GND，代码用 INPUT_PULLUP |
| 按键 · 抚摸 | 5 | 同上 |
| 光敏 AO | 1 | **ADC1_CH0**。刻意选 ADC1（GPIO1–10）：v2 开 WiFi 后 ADC2（GPIO11–20）的模拟功能不可用 |
| 蜂鸣器 + | 15 | LEDC PWM 驱动 |
| 心情灯 | 48 | **板载 WS2812**，零接线。主流丝印为 GPIO48，个别批次是 GPIO38，以板上丝印为准 |

**刻意避开的引脚**（照表绕开即可）：
- GPIO0 / 3 / 45 / 46：strapping 引脚，外接东西可能开不了机
- GPIO19 / 20：USB D+/D−
- GPIO35 / 36 / 37：**N16R8 的八线 PSRAM 占用**，接了必出玄学问题
- GPIO11–20：v2 开 WiFi 后 ADC2 不可用，干脆都不安排模拟功能
- GPIO12 / 13 / 14 / 16 / 17 / 18：**留空**，v2 的 I2S 音频（麦克风 3 根 + 功放 3 根）正好用

供电：全部器件从 DevKit 的 3V3 / GND 排针取电，总电流 < 100mA，USB 供电余量充足。OLED 模块一般板载 I2C 上拉电阻，无需外接。

## 三、软件架构

### 模块划分

```
Ollie/
├── Ollie.ino            // setup/loop + 毫秒级调度器（Arduino IDE 入口）
├── platformio.ini       // VS Code + PlatformIO 配置（可选，见第五节）
├── PetState.h/.cpp      // 状态机：醒/睡、表情优先级
├── Stats.h/.cpp         // 三项数值 + NVS 存档
├── Face.h/.cpp          // 脸部绘制与动画：五种表情、眨眼、眼动、Zzz
├── Buttons.h/.cpp       // 两路消抖按键
├── LightSensor.h/.cpp   // 光敏采样 + 昼夜判定（迟滞）
├── Buzzer.h/.cpp        // 两声"哔哔"
├── MoodLight.h/.cpp     // WS2812 心情灯
└── docs/plan-v1.md
```

两个 IDE 任选其一：模块 `.h/.cpp` 完全通用，只是入口不同（Arduino IDE 用 `.ino`，PlatformIO 用 `src/main.cpp` 抄同样的 setup/loop）。

### 状态机

```
醒来 ──(光敏持续变暗 ≥10s)──▶ 睡眠（数值停掉、精力 +2/min、Zzz 动画、屏变暗）
睡眠 ──(光敏变亮, ADC > 2000)──▶ 醒来

醒着时的表情优先级（高→低）：
  ① 临时开心 3s（喂食/抚摸触发，压过一切）
  ② 饥饿    饱食度 < 30
  ③ 困倦    精力 < 30
  ④ 平静    默认
```

- 睡眠中按键无效（可选彩蛋：抚摸唤醒，一行代码的事）
- v1 不做死亡机制：数值到 0 只影响表情和灯，不会死

### 数值规则

| 数值 | 范围 | 衰减 | 喂食 | 抚摸 | 睡眠时 | 影响 |
|---|---|---|---|---|---|---|
| 饱食度 | 0–100 | −1/分钟 | +20 | — | 停 | <30 → 饥饿表情 |
| 心情 | 0–100 | −1/分钟 | +4 | +15 | 停 | RGB 灯颜色 |
| 精力 | 0–100 | −1/分钟 | — | — | **+2/分钟** | <30 → 困倦表情 |

行为反馈：喂食或抚摸 → 开心表情 3 秒 + 蜂鸣器叫两声（2kHz 方波，80ms–80ms–80ms）。
100 → 0 需 100 分钟，即"每小时照顾一次"的节奏，符合桌宠定位；数值上限 100 截断。

### 存档（NVS）

- `Preferences` 库，命名空间 `ollie`，三个数值打包成一个 struct 按 blob 存，每分钟结算后写一次
- 断电重启后原样恢复。板上没有 RTC，不做"关机期间继续衰减"（保持简单，将来有需要再说）
- 磨损分析：NVS 每条 32 字节、每页 4096 字节约 126 条，即约 2 小时写满一页；Flash 十万次擦写，单页就能撑 20 年以上，实际还有多页轮换。**这个写入频率完全安全**

### 渲染管线（Face 模块）

- 帧率 30fps（每 33ms 一帧），非阻塞
- 画面布局初始值（128×64）：两眼中心 (40, 22) 和 (88, 22)，眼尺寸 24×28 圆角矩形；嘴中心 (64, 46)，宽 28
- 所有表情都是参数化图元，一套绘制函数吃不同参数：

| 表情 | 眼睛 | 嘴巴 | 附加动画 |
|---|---|---|---|
| 平静 | 圆角竖矩形 | 短横线微上翘 | 自动眨眼（每 2–6s 随机，闭合 120ms，眼高压到 4px 再弹回）；眼珠每 3–8s 随机偏移 ±6px 乱瞟 0.5–1s 后回中 |
| 开心 | 上弯弧线（眯眼 ^^） | 大上弯弧 | 触发瞬间嘴做 2 帧开合 |
| 饥饿 | 半闭眼 + 眉角下压 | 下弯波浪线 | — |
| 困倦 | 眼皮垂到 40% 高度 | 小圆 o | 整脸缓慢上下 1px 晃动 |
| 睡眠 | 下弯闭眼线 | 无 | 右上角 "Z" 逐个上浮变大；屏对比度调低 |

- 对外只有一个接口 `face.setExpression(Emotion e, uint32_t holdMs)`，与触发源解耦——**这是为 v2 AI 聊天预留的关键设计**：将来聊天情绪直接调这个函数就能驱动脸

### 调度器（main loop，全部非阻塞）

| 周期 | 任务 |
|---|---|
| 33ms | Face 渲染一帧 |
| 200ms | 按键扫描（消抖） |
| 500ms | 光敏采样（8 次滑动均值）→ 昼夜判定 |
| 60s（DEBUG 时 1s） | 数值结算 + NVS 存档 + 心情灯更新 |

### 心情灯颜色映射（板载 WS2812）

| 状态 | 颜色 | 效果 |
|---|---|---|
| 心情 ≥ 70 | 青绿 | 缓慢呼吸 |
| 心情 40–69 | 琥珀黄 | 常亮 |
| 心情 < 40 | 橙红 | 慢闪 |
| 睡眠 | 深蓝 | 极慢呼吸，亮度压到 10–30% |
| 临时开心 | 粉 | 3 秒渐变（嫌麻烦就粉色常亮） |

- 用 arduino-esp32 内置的 `rgbLedWrite(pin, r, g, b)`（核心 2.x 叫 `neopixelWrite`），不需要装库
- RGB 各通道亮度封顶约 40/255，避免夜间刺眼
- 颜色切换用 200ms 渐变过渡，不要硬跳

## 四、里程碑计划（M0–M7）

每个里程碑独立可验收，**完成一个就 git commit 一次**。

| # | 里程碑 | 内容 | 验收标准 | 预估 |
|---|---|---|---|---|
| M0 | 环境搭建 | 装 IDE + ESP32 板级支持，烧 Blink | LED 闪烁，串口 115200 能打印 | 0.5 晚 |
| M1 | 屏幕点亮 | 接 OLED，跑 I2C Scanner，显示文字 | Scanner 找到 0x3C；屏上显示 "Ollie" | 0.5 晚 |
| M2 | 表情引擎 ★最大块 | Face 模块：五种表情 + 眨眼 + 眼动 | 五表情轮播均正确；自动眨眼随机间隔 2–6s；眼珠乱瞟；30fps 无卡顿 | 2 晚 |
| M3 | 按键互动 | 消抖 + 蜂鸣器 | 按喂食/抚摸 → 开心脸 3s + 两声哔；快速连按不误触、不漏按 | 1 晚 |
| M4 | 数值与存档 | Stats + NVS | 开 `DEBUG_FAST_DECAY`（1 点/秒）观察衰减；中途断电重启，数值与断电前一致 | 1 晚 |
| M5 | 昼夜感知 | 光敏 + 睡眠态 | 串口打印 ADC 原始值标定阈值；手遮光 10s 入睡（Zzz、屏变暗、数值停走、**精力回升**）；手电照立刻醒 | 1 晚 |
| M6 | 心情灯 | WS2812 颜色映射 | 三个心情区间颜色正确；切换有渐变；睡眠呼吸灯；亮度不刺眼 | 0.5 晚 |
| M7 | 整合打磨 | 优先级联调 + 长测 | 遮光又喂食等冲突场景表现正确；**过夜长测**：无死机、无内存泄漏（串口看 uptime/heap）、早晨数值正确 | 1 晚 |

除 M2 和 M5 外都很轻。最可能卡的是 M2 的"画得好看"——那是审美问题不是技术问题，先用表格里的初始参数跑起来再慢慢调。

调试技巧汇总：
- `DEBUG_FAST_DECAY`：衰减 1 点/秒，4 分钟看完整个数值曲线
- 光敏标定：串口每 500ms 打印 ADC 原始值，分别在白天/傍晚/夜晚/手遮四种情况记录，再定阈值
- 上传失败：按住 BOOT 键再点上传

## 五、开发环境

### 路线 A：Arduino IDE 2.x（上手最快）

1. 开发板管理器装 **esp32 by Espressif Systems**
2. 库管理器装 **Adafruit SSD1306**（会自动带上 Adafruit GFX）
3. 板子选项（关键）：

| 选项 | 值 |
|---|---|
| Board | ESP32S3 Dev Module |
| **USB CDC On Boot** | **Enabled**（不开串口没输出） |
| Flash Size | 16MB |
| PSRAM | OPI PSRAM（v1 用不到，但为 v2 提前设好） |
| Partition Scheme | 默认即可（v1 程序很小） |

### 路线 B：VS Code + PlatformIO（工程更干净）

装好 PlatformIO 插件后，`platformio.ini`：

```ini
[env:olllie]
platform = espressif32
board = esp32-s3-devkitc-1
framework = arduino
monitor_speed = 115200
board_build.arduino.memory_type = qio_opi   ; N16R8: 四线 Flash + 八线 PSRAM
board_upload.flash_size = 16MB
build_flags =
    -DCORE_DEBUG_LEVEL=1
lib_deps =
    adafruit/Adafruit SSD1306 @ ^2.5.0
    adafruit/Adafruit GFX Library @ ^1.11.9
```

两条路线产物是同一份固件。建议：一个人玩选 A，打算长期迭代（尤其要上 v2）选 B。

## 六、v2 AI 聊天前瞻 + v1 就要做的预留

### 可行性

ESP32-S3 做 AI 聊天伴侣是**已被验证的路线**：8MB PSRAM 足够 TLS 握手和音频缓冲，WiFi 走 HTTPS/WebSocket 调云端 LLM。社区有非常对口的开源项目 **xiaozhi-esp32**（ESP32-S3 上的 AI 陪伴机器人，含唤醒词、流式对话、OLED 表情），v2 动工前值得通读它的架构。

难点不在"能不能聊"，而在：
1. **音频链路**：要加 INMP441（I2S 麦克风）+ MAX98357A（I2S 功放 + 喇叭），驱动和降噪都是细活
2. **延迟**：唤醒 → 识别 → 生成 → 合成全程 1–3 秒，需要用表情动画把等待"演"出来（如思考表情、听的时候眨眼回应）
3. **成本与隐私**：走商用 API 有按 token 计费和录音上云的问题，需要选型

### v1 现在就做的四个预留（成本≈0）

1. **引脚**：分配表已避开 ADC2 / strapping / USB / PSRAM 占用，GPIO12/13/14/16/17/18 留空——正好是未来 I2S 麦克风 3 根 + 功放 3 根
2. **接口解耦**：Face 模块只暴露 `setExpression(Emotion, holdMs)`，触发源（按键、数值、将来的聊天情绪）一视同仁
3. **数据集中**：数值读写只在 Stats 模块，v2 接云端同步时只动这一个文件
4. **环境**：PSRAM / Flash 选项现在就按 N16R8 配好，v2 直接用

## 附：首次运行检查单

- [ ] I2C Scanner 找到 0x3C（找不到先查 SDA/SCL 是否接反）
- [ ] 光敏四种场景（白天/傍晚/夜晚/手遮）的 ADC 原始值已标定，阈值已写入

- [ ] 遮光 10s 入睡 / 照亮即醒，来回五次不横跳
- [ ] 睡一觉（遮光）后精力明显回升
- [ ] 过夜长测通过
