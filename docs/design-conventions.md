# 设计规范 · design-conventions

写代码前先读一遍；评审代码时按本规范对齐。

## 1. 语言与命名

- 标识符、文件名用英文；**注释用中文**，说"为什么"而不是"这行干什么"
- 类名 `PascalCase`；方法/变量 `camelCase`；宏与常量 `UPPER_SNAKE`；引脚宏以 `PIN_` 开头
- 文件一类一文件，`.h` 与 `.cpp` 同名成对；头文件一律 `#pragma once`

## 2. 架构约束（硬性）

1. **配置集中**：所有引脚、阈值、周期、开关进 `Config.h`。业务代码里出现裸数字即违规（几何绘制参数这类"美术初始值"允许留在 Face.cpp 顶部并注释标明可调）
2. **非阻塞**：`loop()` 及任何 `update()` 路径禁止 `delay()`、阻塞等待；时间判断一律 `now - last >= period` 写法（无符号溢出安全）
3. **单一职责归属**：数值读写只在 Stats；醒/睡状态只在 PetState；每个外设的时序细节（消抖/迟滞/渐变）封装在自己的模块里
4. **对外接口最小化**：模块间通过少量公开方法交互（Face 只暴露 `setBase`/`setExpression`）；禁止模块间互摸私有状态
5. **兼容性用垫片**：依赖的核心 API 有版本差异时（如 LEDC、WS2812），在实现文件内做 `#if` 垫片，不锁核心版本

## 3. 代码风格

- 缩进 4 空格；大括号 K&R（函数左括号不换行）
- 每个模块 `.h` 顶部写 2–5 行职责注释；公开方法带一行用途注释（做什么、何时调用）
- 日志用 `LOGF`（`OLLIE_DEBUG` 控制），事件级打印即可，禁止每帧刷屏

## 4. Git 规范

- 单分支 `main` 直推；**每完成一个可验收单元提交一次**（里程碑/单个小功能）
- 提交信息 Conventional Commits + 中文描述：`feat: …` / `fix: …` / `docs: …` / `test: …` / `chore: …`；正文列要点
- 提交前自查：`pio run` 过、`bash test/run_tests.sh` 过、无密钥/无临时文件

## 5. 文档同步义务（改代码必须连带）

| 改动 | 必须同步 |
|---|---|
| 引脚 / 阈值 / 周期 | `Config.h` 为主，同步 docs/tech-spec.md 引脚表 |
| 验收标准 / 新需求 | docs/requirements.md |
| 构建测试流程 | docs/procedures.md |
| 任何开发过程 | devlog/ 当日日志 + TODO.md |

## 6. 测试义务

- 纯逻辑（数值/状态机/判定/时序）改动 → 补/改 `test/` 单测并全绿
- 新增外设或渲染改动 → 至少过 Wokwi 仿真冒烟（见 procedures.md §3）
- 硬件相关改动 → 实机验收后方可勾掉 TODO

## 7. 安全红线

- 仓库**永远不出现**密钥、口令、私网地址（v2 的 API key 存 NVS，经配置页写入）
- `.gitignore` 新增构建产物目录时同步登记，防止大文件混入
