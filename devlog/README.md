# 开发日志（devlog）

按天记录开发过程：做了什么、为什么这么决定、踩了什么坑、接下来做什么。

## 文件说明

| 文件 | 用途 |
|---|---|
| `YYYY-MM-DD.md` | 每个开发日/开发会话一篇，命名用日期（一天多篇加后缀 `-2`） |
| [TODO.md](TODO.md) | 待办事项总表，唯一的进行中任务清单（完成一项勾一项，并同步到当日日志） |

## 日志格式模板

```markdown
# 2026-XX-XX

## 完成
- （做了什么，附关键文件/提交号）

## 决策
- （做了什么取舍、为什么。将来翻日志能找到理由）

## 问题与坑
- （现象 → 原因 → 解法/绕过；没解决的写"待查"）

## 下一步
- （链接到 TODO.md 对应条目）
```

## 写作规则

1. **当天写**：隔天细节就丢了；一次会话结束前花 5 分钟补上
2. **决策比流水账重要**：只记"改了 3 个文件"没有价值，记"为什么按键扫描从 200ms 改成 20ms"有价值
3. **坑要写全**：现象、原因、解法三要素，将来同类问题先翻日志
4. 完成的待办在 TODO.md 勾掉，并在当日日志"完成"里留一行记录
