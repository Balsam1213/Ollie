# 2026-10-30 · v1.2 台词系统：Ollie 会说话了

## 完成

- **离线台词系统全量落地**（roadmap v1.2 卡第一项）：
  - `DialogLines.h`：九个场景台词池（平静/饿/困/丧/入睡/醒来/喂食/抚摸/冷落），中文+颜文字，每句 ≤8 字
  - `tools/genfont.py`：扫描台词表自动生成 12×12 中文字库（微软雅黑，91 字形 ≈3KB Flash），台词与字库永不失配
  - `Face` 重构：覆盖队列（最多 2 项，表情/台词两种）+ UTF-8 解码器 + 字形二分查找 + 整屏居中排版（单行 ≤8 字、两行自适应）
  - `Dialog` 驱动器：喂食/抚摸"先笑 1.4s 再说话"、入睡/醒来必说、数值跌破阈值说一次、空闲 90–240s 闲聊（池随主导情绪）、30 分钟冷落撒娇、任意两句 ≥20s 防刷屏
- **验证**：单测 165 → **289 项全过**（新增：台词表逐句长度校验、真实字库查询含字形有墨检查、选句不重复、事件/跨越/睡着安静全链路）；固件编译成功，RAM 16.2% / Flash 40.5%（字库仅 +0.2%）

## 决策

| 决策 | 理由 |
|---|---|
| 自制 12×12 字库而非引第三方字库库 | 只需台词表出现的 91 个字符；genfont.py 保证台词与字库自动同步，比 U8g2 全字库省 ~100KB |
| 台词整屏短暂显示而非底部常驻 | 128×64 塞不下"脸+常驻中文小字"；整屏 2.2s 更像"说话"这个事件 |
| 喂食/抚摸 = 开心脸 1.4s → 台词 2.2s 排队播放 | 保留原有笑脸反馈，又让台词像"说完笑再说的话"——覆盖队列天然支持 |
| Face 覆盖从单 override 升级为 2 项队列 | 台词要"排在当前表情之后"，单槽会互相冲掉 |
| 台词表用 C++17 inline 变量 + 测试内容比较（strcmp） | static 头文件数组每 TU 一份拷贝，指针相等断言跨单元不可靠；内容比较稳定 |
| 睡前台词先于变暗播放 | 台词可读性优先；播完自动进入暗屏睡眠 |
| 闲聊挂在 60s 结算节拍而非每帧检查 | 台词精度秒级足够，省一处调度项；触发延迟 ≤60s 无感 |

## 问题与坑

- **跨编译单元字面量指针不相等**：static 头文件数组导致 Dialog.cpp 与测试各持副本，指针断言全挂 → 改 strcmp 内容比较 + inline 变量。教训：指针相等只适合同一 TU 内的常量
- genfont.py 渲染空白字符自动跳过并警告（防止字库里存全零字形浪费查找）
