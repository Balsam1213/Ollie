# 2026-10-28（二） · v2.0 网页聊天编码完成

## 完成

按 roadmap §2 v2.0 卡实现，全部通过本地验证：

- **ChatLogic**（纯逻辑，零 Arduino 依赖）：人设 prompt（含三项数值快照注入 + 低状态情感提示）、JSON 转义/还原（\uXXXX 含代理对→UTF-8）、API 响应 content 提取（跳串扫描，不会被 reasoning_content 等字段值内部的 `"content"` 文本误命中）、回复解析（严格 JSON + ``` 围栏容忍 + 非 JSON 兜底）、情绪名映射、请求体组装
- **NetConfig**：凭据存 NVS；无凭据开 `Ollie-Setup` 热点 + 配网页（captive DNS 重定向）；STA 非阻塞连接（25s 超时、15s 退避、连败 2 次也开热点补救）；连上起 mDNS（ollie.local）；设置保存后延时重启
- **LLMClient**：FreeRTOS 任务（core 0）跑 HTTPS（WiFiClientSecure + HTTPClient），loop 只投递/收结果，渲染不受 1–3s 延迟影响；结果带序号保留供网页轮询与表情应用两个消费者
- **WebChat**：聊天页（手机气泡 UI + 数值顶栏 + 409 忙拒绝）、设置页（逐项空值保持）、`/api/chat` 投递、`/api/result` 轮询、`/api/state` 快照
- **集成**：Ollie.ino 联网状态编排（连上→web.start；掉线→web.stop + 心情灯蓝闪 2.5s）；MoodLight 加 netLostFlash
- **验证**：单测 165 项全过（新增 ChatLogic 36 项）；固件编译成功，RAM 16.2% / Flash 40.3%

## 决策

| 决策 | 理由 |
|---|---|
| LLM 调用用 FreeRTOS 任务而非"调度器状态机"（roadmap 原文） | 目标相同（渲染不被延迟阻塞）；TLS 握手无法可靠分片，任务是最稳解；roadmap 意图达成，手段记档 |
| 网页应答采用"POST 立即 202 + 轮询 /api/result" | handler 若原地等 LLM 会阻塞 handleClient → 冻结表情；轮询让渲染完全无感 |
| 手写最小 JSON 工具（转义/找 key/取值）而非引入 ArduinoJson | 契约自己定（{reply,emotion}），约 150 行可控可测；省一个依赖；PC 单测直接覆盖 |
| 聊天结果带递增序号（seq）保留至下次请求 | 两个消费者（网页轮询、表情应用）互不抢占，各自用序号去重 |
| TLS 用 setInsecure 跳过证书校验 | 桌宠场景务实取舍：请求由局域网主人发起，校验成本（嵌 CA/维护）与威胁不匹配；留 TODO，将来可加指纹校验 |
| 系统提示词进堆（std::string）而非 PROGMEM | prompt 需要运行时注入数值，且仅 ~600B；换取 ChatLogic 可在 PC 上完整测试 |
| 配网连败 2 次也开热点 | 密码配错时主人还有补救入口，不用重新擦 Flash |
| 版本宏 OLLIE_VERSION="2.0.0-dev" 进 Config.h 并随开机打印 | roadmap 横切项（版本规范）提前落地一半；"dev"后缀待联网实测后转正 |

## 问题与坑

- **PC 单测枚举名歧义**：Face 的全局 `Emotion` 与 `chat::Emotion` 在 `using namespace chat` 下冲突 → 测试内全部用 `chat::` 限定
- **appendCodepoint 漏 4 字节 UTF-8**：😀（U+1F600）是代理对合成码点 >0xFFFF，首版 3 字节编码出 0xFF 垃圾 → 单测逮住，补 4 字节分支。教训：代理对测试必须用真实 emoji
- **HTTPClient::POST 无 const char*+size 重载** → 用 String 重载
- **Flash 13% → 40%**：WiFi/TLS 栈 ~900KB，符合预期不是泄漏；RAM 7.6% → 16.2% 同理
