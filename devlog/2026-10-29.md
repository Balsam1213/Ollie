# 2026-10-29 · 首次实机烧录救砖：No serial data received

## 完成

- 用户开始实机烧录，Arduino IDE 2.3.10，报错：`Connecting......` → `Failed to connect to ESP32-S3: No serial data received`
- **诊断**：编译成功（1.16MB / 88%）说明工程配置全对；失败发生在 esptool 与芯片的下载握手——芯片未进入下载模式。S3 双 USB 口的经典坑，非代码/接线问题
- 给出三步解法（手动下载模式 / 换 COM 口上传 / 换线+降速）并等用户回报结果
- README 同步三处：烧录节新增"上传连不上？三步救"块、排查表拆成两行（含"烧录成功但 COM 口无日志"的正常现象说明）、分区方案建议改为 16M Flash APP≥3MB

## 决策

| 决策 | 理由 |
|---|---|
| 上传/看日志分工：**上传走 COM 口，日志走 USB 口** | 串口芯片在硬件层自动帮芯片复位进下载模式，上传最稳；USB CDC 日志走原生 USB 口。原 README 只说了插 USB 口，不够 |
| 分区方案从"默认 4MB"改为"16M Flash APP≥3MB" | v2 固件 1.16MB，默认方案 APP 分区 1.25MB 只剩 12% 余量，v1.2/v2.1 必爆；16MB Flash 方案给 3MB+ 且与 PlatformIO 一致 |
| 手动下载模式写成"按 BOOT→短按 RST→松开"而非"按住 BOOT 点上传" | 前者把芯片锁死在下载模式，不依赖 IDE 时序，成功率最高；后者作为简化替代保留 |

## 问题与坑

- **报错 `No serial data received` ≠ 接线/代码问题**：编译通过 + COM 口出现 = 驱动、工程、USB 线都正常，只是下载模式握手失败。先强制进下载模式，别去查接线浪费时间
- 原引导语"按住 BOOT 再点上传"对 USB 口（原生 USB-Serial-JTAG）有时序依赖，偶发失败；对 COM 口几乎必成
